Zsh startup, without the mystery

Login and interactive are two different questions.

A shell can be login, interactive, both, or neither. This guide follows one outer shell and one shell opened inside it, then maps that behavior to your .zprofile and .zshrc.

Start with two switches

Login describes the shell's role in starting a session. Interactive describes whether a person is using the shell through a prompt.

These switches are independent. “Login shell” does not mean “a shell where you can type,” and “interactive shell” does not mean “the first shell.”

Remember: login sets up a session; interactive sets up a conversation.

A login shell prepares the session

Zsh reads ~/.zprofile when it is started as a login shell. This is a good place for stable environment values that child processes should inherit, such as PATH, locale, and your editor.

The entrance analogy has a limit: programs can request login mode directly with zsh -l. It is a process flag, not proof that a password was entered.

An interactive shell talks to you

Zsh reads ~/.zshrc when it expects a person to type commands. This is where prompt styling, aliases, completion, key bindings, and interactive tool setup belong.

Opening another Zsh inside your terminal creates another interactive shell, so .zshrc runs again. That is why expensive setup in this file can make every new shell feel slow.

A shell can be both, one, or neither

The bottom-right box is common when a terminal starts a login shell with a prompt. The top-right box is common when you start another Zsh inside that shell.

A script usually gets neither login nor interactive behavior. This is why aliases from .zshrc should not be treated as commands that scripts can depend on.

Follow one shell into another

Run zsh -l -i. It is both login and interactive, so it reads .zprofile and then .zshrc.

Now type zsh. The inner shell is interactive but not login. It inherits the outer shell's exported PATH and locale, then reads .zshrc for its own prompt and aliases. It does not need to rebuild the stable environment.

The files have separate jobs

  • .zshenv: tiny settings required by every Zsh, including scripts.
  • .zprofile: stable exported environment for a login session.
  • .zshrc: prompt, aliases, completion, and interactive tools.
  • .zlogin: rare actions that must happen late in login startup.

For your setup, keep both files focused

Keep stable exported values in the tracked .zprofile, with macOS-only Homebrew settings behind a platform check. Put prompt behavior and interactive tools in .zshrc.

Your repository's .zlogin is empty, while this machine's copy is generated by Zim. There is no benefit in tracking that generated file today.

A useful test: child programs need profile values; only a person at a prompt needs zshrc behavior.
